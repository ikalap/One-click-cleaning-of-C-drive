# 原理

1. 扫描: 按 33 类预定义规则检查指定目录/系统位置，得到可清理条目及其数量、占用大小。
2. 选择：结果列表展示给用户，可全选、取消全选或逐条勾选。
3. 清理：删除用户选择所有文件（文件优先进回收站，目录内文件直接删除）
4. 备份：删除前默认把文件备份到指定目录（按时间戳分文件夹），可在备份管理中一键恢复

# 配置

## 1. 扫描目标（`../scanners/scan_targets_config.py`）

所有扫描路径与规则的**单一数据源**，集中在 `SCAN_TARGETS` 字典中，键为结果分类 key。
UI 的分类名 `CATEGORY_NAMES` 与结果顺序 `ALL_RESULT_KEYS` 均由它派生，因此这里也是
显示名与展示顺序的唯一来源。

通用扫描项字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `display_name` | 是 | 显示名称，UI 分类名直接取此值 |
| `mode` | 是 | `files`：递归收集文件，每个文件一条记录；`path`：每个路径一条记录（目录聚合总大小，文件取自身大小） |
| `paths` | 是 | 路径列表，支持 `%ENVVAR%` 环境变量与 `*` `?` `[]` glob 通配符；变量不存在时该条路径被跳过 |
| `extensions` | 否 | 扩展名白名单（小写含点，如 `['.log', '.tmp']`），仅 `mode='files'` 有效 |
| `older_than_days` | 否 | 仅收集修改时间早于 N 天前的文件，仅 `mode='files'` 有效 |
| `count_files` | 否 | 为 `mode='path'` 的记录附带 `file_count` 字段（文件数量） |
| `dedicated` | 否 | 专用扫描器的 import path，见第 3 节；与通用字段互斥 |

### 示例：新增一个配置驱动的清理项

```python
'my_cache': {
    'display_name': '我的应用缓存',
    'mode': 'path',
    'paths': [
        r'%LOCALAPPDATA%\MyApp\Cache',
        r'C:\Users\%USERNAME%\AppData\Local\MyApp\Temp',
    ],
},
```

加完即生效，无需新增 Python 文件：扫描器、UI 分类名、展示顺序都会自动包含它。

## 2. 通用扫描器：MFT 优先，os.walk 回退

通用扫描项（`SCAN_TARGETS` 中未标 `dedicated` 的）由**同一个** `MftScanStrategy`
实例统一负责，默认使用 `../scanners/mft_scan_strategy.py`：

- `MftBackend`：对 C 盘**只解析一次 MFT**，得到所有活跃条目，再按 `SCAN_TARGETS`
  的通用规则**一次性分发**，产出各分类结果；结果与原始条目在进程内缓存，
  供所有通用扫描器及 `large_files` 共享；
- `MftDirectoryScanner.scan()`：从后端取回本分类的结果；
- 当 `mftparser` 未安装、缺少管理员权限或磁盘非 NTFS（`ScanVolume` 抛异常）时，
  `MftBackend.ensure()` 返回 `False`，自动回退到 `../scanners/io_scan_strategy.py` 的
  `IoScanStrategy`（`os.walk` 遍历），功能保持一致。

MFT 分发逻辑与 `IoScanStrategy` 等价：`mode='files'` 逐条收集并套用
`extensions` 过滤；`mode='path'` 按配置路径聚合；同一分类下重复的路径配置自动去重。
`older_than_days` 会额外用 `os.stat` 复核修改时间（MFT 时间字段索引不稳定）。

回退方案 `IoScanStrategy` 流程：

1. `_iter_paths()`：展开 `%ENVVAR%` 环境变量，遇到 glob 通配符则用 `glob.glob` 展开；
2. 对每个路径先检查存在性与 `context.is_safe_path()`（安全路径直接跳过）；
3. `mode='files'`：若路径是文件则收集该文件，否则 `os.walk` 递归，逐文件套用
   `extensions` / `older_than_days` 过滤后写入结果；
4. `mode='path'`：文件取自身大小，目录用 `_dir_size_and_count()` 统计总大小与文件数，
   总大小为 0 则不记录。

错误处理一致：`PermissionError` / `FileNotFoundError` / `OSError` 一律跳过或记警告，不中断扫描。

## 3. 专用扫描器

`build_strategies()` 最终只实例化 **1 个通用策略 + 各专用策略各 1 个**（例如 5 个专用项
即共 6 个实例），而不是每个分类 key 一个实例；每个策略用 `keys` 属性声明自己负责的
结果 key（单 key 策略默认 `[key]`）。

无法用配置表达的逻辑保留为独立策略类，通过 `dedicated` 字段引用：

| key | 类 | 特殊之处 |
|---|---|---|
| `cache` | `scanners.dedicated.browser_cache.BrowserCacheScanner` | 动态枚举 Firefox profile 目录 |
| `media_cache` | `scanners.dedicated.media_cache.MediaCacheScanner` | glob 通配符 + 文件/目录混合 |
| `app_logs` | `scanners.dedicated.app_logs.AppLogsScanner` | glob + 30 天时限 + 文件/目录混合 |
| `installer_cache` | `scanners.dedicated.installer_cache.InstallerCacheScanner` | 扩展名或超期二选一 + `subtype` + 特殊目录 |
| `large_files` | `scanners.dedicated.large_files.LargeFilesScanner` | 复用 `MftBackend` 的条目做 Top-N 堆排序；MFT 不可用时回退 os.scandir |

新增专用项时，把类文件放入 `scanners/dedicated/`，并在 `SCAN_TARGETS` 中写：

```python
'my_special': {
    'display_name': '特殊项',
    'dedicated': 'scanners.dedicated.my_special.MySpecialScanner',
},
```

## 4. 展示名与顺序

- `CATEGORY_NAMES`：`{key: display_name}`，由 `SCAN_TARGETS` 自动生成；
- `ALL_RESULT_KEYS`：`SCAN_TARGETS` 的键列表，其顺序即 UI 分类的展示顺序。

二者都由 `scanners/__init__.py` 导出，不要在 UI 层重复定义。

## 5. 运行期配置（`CleanerLogic.set_options`）

清理选项通过 `CleanerLogic.set_options(options)` 更新：

| 选项 | 类型 | 说明 |
|---|---|---|
| `backup` | `bool` | 删除前是否备份到 `backup_dir` |
| `backup_dir` | `str` | 自定义备份目录 |
| `max_backups` | `int` | 最多保留的备份数量 |
| `max_backup_size` | `int` | 单个备份大小上限（字节） |

扫描项没有运行期开关，固定按 `SCAN_TARGETS` 全量扫描。

## 6. 安全路径

`CleanerLogic.__init__` 中的 `self.safe_paths` 定义不会被扫描或清理的目录，通过
`ScanContext.is_safe_path()` 在扫描阶段剪枝，默认包含：

- `C:\Windows\System32`
- `C:\Windows\SysWOW64`
- `C:\Program Files`
- `C:\Program Files (x86)`

## 7. `config.py` 说明

`config.py` 当前**仅 `APP_NAME`、`VERSION` 被实际使用**。文件中的
`DEFAULT_CONFIG`、`SAFE_PATHS`、`CLEANABLE_FILE_TYPES`、`TEMP_PATHS` 等常量尚未接入代码，
属于历史遗留；扫描相关的真实配置请看 `../scanners/scan_targets_config.py`。
